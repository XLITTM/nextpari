# SoftAggregator operator test

The existing demo catalog only publishes provider records marked `play_for_fun_supported`. The operator test stays on the casino branch's protected Vercel Preview and has no website or Android menu entry.

1. Confirm the separate SoftAggregator site, enabled currency, exact game ID, launch origins and credit terms with SoftAggregator. The operator billing credit and synthetic player balance are separate.
2. Use a dedicated non-evicting Upstash Redis database with no NextPari data. Configure `SOFTAGGREGATOR_TEST_REDIS_URL` and `SOFTAGGREGATOR_TEST_REDIS_TOKEN` as branch-scoped Preview secrets. For initial connectivity testing, seed the wallet hash's `balance` field to zero with `HSETNX`. Obtain the hash key from `testWalletKey(username, currency)`. Amounts are nonwithdrawable synthetic minor units.
3. Set `SOFTAGGREGATOR_TEST_USERNAME` to `np_test_` followed by 24 random lowercase hex digits. Set `SOFTAGGREGATOR_TEST_CURRENCY` to a provider-confirmed test currency. Generate independent server-side values for `SOFTAGGREGATOR_TEST_PLAYER_PASSWORD` and `SOFTAGGREGATOR_TEST_OPERATOR_TOKEN`. Set the separate site's rotated `SOFTAGGREGATOR_TEST_API_LOGIN`, `SOFTAGGREGATOR_TEST_API_PASSWORD` and `SOFTAGGREGATOR_TEST_SALT` in Preview secrets.
4. Use a stable provider-reachable ingress scoped to the callback path and documented provider IP. Keep Vercel Authentication on the rest of Preview. Verify the handler receives the actual provider IP in the trusted Vercel header and that access logs redact signed query parameters. Configure `SOFTAGGREGATOR_TEST_CALLBACK_HOST` and `SOFTAGGREGATOR_TEST_CALLBACK_ENABLED=1` only after that ingress is in place. Register only the dedicated test site's callback at `/api/internal/casino/softaggregator/test-callback`. Set `SOFTAGGREGATOR_TEST_CALLBACK_VERIFIED=1` after an actual signed balance callback succeeds.
5. With `SOFTAGGREGATOR_TEST_OPERATOR_ENABLED=1`, the protected Preview route `/api/internal/casino/softaggregator/test-operator` takes same-origin JSON POST requests with bearer authentication. Supported actions are `capabilities`, `createPlayer` and `launch`. Configure `SOFTAGGREGATOR_TEST_GAME_ID`, `SOFTAGGREGATOR_TEST_LAUNCH_ORIGINS` and `SOFTAGGREGATOR_TEST_COUNTRY` from verified provider and test details. Launch also takes `device` set to `desktop` or `mobile`.
6. Set `SOFTAGGREGATOR_TEST_STANDARD_LAUNCH_APPROVED=1` only after the owner's explicit approval for the money-bearing test. This also enables debit and credit callbacks for the single test identity. Verify actual game rendering and callback outcomes. Close outstanding test rounds before disabling the callback.

The callback checks the documented legacy key and full-payload signature, timestamp freshness and exact test identity. Fresh duplicate calls return their original result without applying the balance movement again. A conflicting use of the same ID is rejected. Rollbacks use the action supplied by SoftAggregator and standalone credits are valid. The atomic Redis command stores only hashes, normalized operation fields and the outcome alongside the test balance. The application does not log signed URLs or provider responses.

Provider reference: https://softaggregator.com/docs.html
